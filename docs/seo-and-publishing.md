# SEO and publishing implementation

Slice 5 is local implementation, not a production launch. Owner instructions are in [content-editing.md](content-editing.md). The generated Services pillar and nine service drafts have since been removed at the owner's request. Homepage summaries remain editable in Home; Services is empty for future owner-authored pages. Original images remain private.

## Rendering and URL policy

`src/domain/seo.mjs` resolves manual page values against site defaults. Title falls back to the page heading/title; descriptions and images fall back to Site settings. Social title/description have optional independent overrides. One canonical link and robots/OG/Twitter tags render in the initial HTML. Canonicals normally use `SITE_URL` and trailing-slash content routes. A valid absolute alternate canonical is permitted and excludes the local route from the sitemap. Blog search/topic queries canonicalize to `/blog/` and are noindex. The site does not invent article publication dates.

`SITE_URL` must be an origin with no path/query/credentials. Production requires an explicit HTTPS origin. Indexing is enabled only when `CMS_ENV=production` and `PUBLIC_INDEXING_ENABLED=true`. Local/staging stays noindex and robots disallows all crawling. This indexing flag is not authentication; hosted staging still needs access protection in Slice 7. Indexing-enabled production robots allows the public site, including individual noindex pages, and disallows admin/API/preview. The sitemap includes only published, indexable, self-canonical page/article/reviewed-service URLs and excludes active redirect sources. It reads fresh data. No Search Console property or submission has been configured.

Structured-data templates emit visible Person, WebSite/WebPage, BlogPosting, Service and BreadcrumbList facts. They do not generate ratings, reviews, prices, credentials, or guessed dates. A per-page/site checkbox can disable them; there is no arbitrary schema editor. JSON serialization escapes script-breaking characters. Meaningful selected images use alt text and generated responsive/social sizes; sharing tags use actual file dimensions. Published image version URLs change with updatedAt. A selected private/unavailable image blocks publication. An absent optional image or decorative empty alt does not.

## Publishing and references

`src/publishing.ts` runs validation on the server, including direct REST/Local API publication. Genuine draft saves remain possible; `draft=true` does not bypass checks when publishing. Services require reviewed nonempty detail copy. Required internal references and named fragments must resolve to published targets. Unsafe URLs and duplicate section anchors block saving/publication through field/schema validation. Optional missing links are omitted from rendering and reported as suggestions. Metadata lengths, duplicate titles/descriptions, skipped heading levels, generic anchor wording and large images are suggestions. External URL availability is not fetched automatically.

Required incoming published references guard unpublish, deletion and removal of a named section. Navigation is always required; content buttons/links can opt into this rule. Media publication changes/deletion also check published uses. Related selections and automatic content lists are optional and disappear when unavailable. The Publishing tab shows record links to incoming sources, field-specific messages, effective metadata and a sharing summary.

Published service/article slug changes update managed aliases in the same Payload transaction. Multiple renames collapse to one hop; restoring an earlier managed address removes the conflicting alias. Deleting a target removes its managed aliases; unpublishing stops them serving. Manual redirects validate source/destination availability and reject reserved paths, live-page shadowing, duplicate sources, loops and chains. Next's Node Proxy emits 308 permanent / 307 temporary GET/HEAD responses. Local destination queries are retained when no destination query is set; external redirects do not forward visitor queries. System/API/admin/preview and asset traffic bypass this public routing lookup. Database errors produce 503 without stale JSON fallback.

## Refresh and deployment limits

All public pages, metadata, navigation, related lists, routing and sitemap use dynamic fresh database reads. React cache deduplicates only within a render. There is no persistent full-route/data cache or regeneration queue to invalidate. Public and redirect responses use no-store. Publishing applies on the next request; an already-open browser page must reload. The owner can check the actual published HTTP response/title and retry. A failed check is not presented as a successful refresh. External search/social crawler caches are outside application control. Production hosting/CDN configuration must retain this behavior or implement tested invalidation before release.

Uploads are still local disk. Slice 6 now implements private inquiry storage and notification retries; real email activation requires sending-service setup. Persistent production storage, backups, protected staging, final domain/provider choices and deployment remain release work. The parent original calculator/styles/assets remain build dependencies.

## Verification

Run `npm test`, `npm run typecheck`, `npm run test:integration`, `npm run build`, then `npm run verify:seo`. The latter serves the production build on loopback port 3002, creates a guarded disposable UTF8 database, imports fixture copies, tests publication and real HTML/HTTP redirects using example.test canonical URLs, and removes the database and fixture uploads. It does not publish actual local owner content or follow external redirects. `verify:content` runs the content-only lifecycle. Reports: [HTTP](slice5-http-checks.json), [browser](slice5-browser-checks.json), [local content state](slice5-local-import-state.json). Calculator regression tests remain in the parent app.

The pure tests cover nonproduction indexing defaults and script escaping; database tests cover role checks, required references and transactional routing; HTTP tests validate initial head tags, actual social dimensions, schema, sitemap/robots, filtered URLs, protected previews, redirect status/Location and next-request freshness. Browser checks verify the owner controls and responsive templates. Local timings do not establish production Core Web Vitals or search rankings.

Policy references: [Google canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [Google noindex guidance](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [structured data policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies), [Service vocabulary](https://schema.org/Service). Next behavior was checked against the installed version's metadata, robots, sitemap, Proxy and image configuration docs before implementation.
